# PDF 본문 페이지와 갱신 이미지의 정확성

사용자 요청: 기존 검토에서 남은 본문 페이지 번호와 갱신 PDF 이미지 캐시 문제를 우선 수정한다.

## 확인한 원인과 범위

- `build_chunks`의 본문 버퍼는 페이지가 달라도 이어 붙이고 `buffer_page`는 첫 값만 유지한다. 다음 페이지에만 있는 문장이 앞 페이지로 인용될 수 있다.
- `parse_pdf(force=True)`가 새 JSON을 만들더라도 `pages/pN.png`는 남는다. `render_pages`와 `get_page_image`는 파일이 있으면 예전 그림을 사용한다.
- 본문(문단·목록·캡션)의 페이지 변경 시 버퍼를 먼저 비운다. 알려진 페이지와 누락된 페이지도 섞지 않는다. 같은 페이지의 합치기, 제목 경로, 문장 분할·overlap은 유지한다.
- 실제 PDF 변환을 수행하고 JSON을 정상적으로 읽은 뒤 해당 문서의 `pN.png` 캐시를 모두 무효화한다. 자동 이미지 대상이 아닌 페이지와 새 PDF에서 없어진 페이지도 포함한다. 캐시 JSON 재사용 및 변환/JSON 오류 때는 기존 PNG를 보존한다.
- 원본이 없는 문서의 기존 이미지 열람은 유지한다. 운영 자료는 자동 재색인하지 않는다. 이미 저장된 청크의 페이지 번호를 고치려면 해당 문서 재파싱이 필요하다.
- 기존 연속 페이지 표 병합 규칙과 단일 `page` API 계약은 이번 본문 버퍼 수정에서 변경하지 않는다.

## 검증

합성 파싱 트리로 페이지·종류·제목·누락 페이지·긴 본문 경계를 검증한다. 임시 PDF를 두 가지 내용으로 생성해 실제 PNG와 서비스 반환 이미지를 비교한다. 파서 외부 변환만 대체하고 파싱·청킹·이미지 렌더·저장·검색 코드는 실제 경로를 사용한다. 각 수정은 실패하는 회귀 테스트, 수정, 전체 pytest, 별도 커밋 순서로 진행한다.
