# MCP 인스턴스 간 색인 충돌 방지

사용자가 승인한 공용 잠금과 고유 임시 파일 방식으로 구현한다.

## 동작

- 같은 `RAG_DATA_DIR`를 사용하는 MCP 및 CLI의 변경 작업은 한 번에 하나만 허용한다. 후발 요청은 기존 API처럼 `ok=False, status="busy"`로 즉시 반환하며 자동 대기열을 만들지 않는다.
- 잠금은 PDF 파싱 전 획득하고 임베딩, Qdrant 교체, 청크·매니페스트 저장까지 유지한다. 삭제·재색인·원본 경로 변경도 같은 잠금을 사용한다.
- 비동기 색인은 요청 스레드에서 잠금을 획득해 작업 스레드의 `finally`에서 해제한다. 작업 실패·스레드 시작 실패·프로세스 강제 종료 후에도 다시 획득할 수 있어야 한다.
- `data/.locks/mutation.lock`의 첫 바이트를 OS 파일 잠금으로 보호한다. Windows는 `msvcrt.locking`, POSIX는 `fcntl.flock`을 사용한다. 잠금 파일은 삭제하지 않는다. 파일 존재 여부나 PID로 잠금을 판단하지 않는다.
- `chunks.jsonl`의 임시 파일과 매니페스트 임시 파일은 UUID를 붙여 작업별로 구분하고 실패 시 자기 파일만 정리한다.
- 검색·조회는 쓰기 잠금을 획득하지 않는다. 데이터 폴더가 다른 독립 저장소는 서로 잠그지 않는다.

## 범위와 한계

기존 서비스 진입점에 공용 쓰기 잠금을 연결한다. 직접 `Indexer`나 이관 스크립트로 저장소를 조작하는 관리 작업은 MCP를 중지한 뒤 수행하는 기존 운영 절차를 따른다. 서로 다른 데이터 폴더나 서로 다른 PC에서 같은 Qdrant에 쓰는 분산 환경은 이번 수정 범위에 포함하지 않는다. 문서별 병렬 쓰기, 자동 재시도, DB와 파일 간 크래시 원자성, 페이지 캐시 갱신은 별도 과제다.

## 검증

기존 코드에서 독립 서비스와 실제 자식 프로세스의 동시 획득이 허용되는 실패를 확인한다. 수정 후 동시 요청 차단, 완료·예외·강제 종료 뒤 재획득, 비동기 작업 완료까지 유지, 검색 허용, 고유 임시 파일을 검증한다. 운영 데이터·Qdrant·모델을 사용하지 않고 임시 저장소와 가짜 임베딩을 사용한다. 전체 pytest 통과 후 변경 파일만 커밋한다.
