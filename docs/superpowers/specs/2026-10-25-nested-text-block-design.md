# 중첩 본문 색인 누락 방지 — 검토 초안

작성일: 2026-10-25. 상태: 사용자가 이 설계로 구현 진행을 승인함.

## 목적과 확인된 문제

PDF 파서가 만든 `text block` 안의 제목·문단·표·목록을 색인에 포함하여,
신규 PDF 처리와 `reparse=True` 재색인에서 본문 누락이 재발하지 않게 한다.

`ParsedDoc.iter_blocks()`는 현재 루트 `kids`만 반환한다. `build_chunks()`와
`extract_doc_meta()`는 이 반환값을 사용하지만 `text block` 자체를 본문으로
해석하지 않는다. 과거 문서별 데이터 보정으로 해결한 문제가 서버 코드에는 남아 있다.

2026-10-25에 원본 백업 JSON과 현재 코드로 읽기 전용 재현:

| 문서 | 중첩 text block 수 | 현재 코드가 생성한 청크 | 현재 보정 데이터 청크 |
| --- | ---: | ---: | ---: |
| IBMS 감사자용 | 119 | 5 | 120 |
| IBMS 업무담당자용 | 83 | 39 | 116 |

두 백업의 text block에는 직접 content가 없으며 page number가 있다.
이 수치는 검색 품질 점수가 아니라 파싱·청킹 누락의 재현 근거다.
기존 `uv run pytest -q`는 통과했다. 현행 테스트만으로 이 누락을 탐지하지 못한다.

## 검토한 접근

1. **공통 파서 순회 보완 — 권장.** `ParsedDoc.iter_blocks()`에서 text block만
   투명한 컨테이너로 처리한다. 청킹과 문서 메타데이터 추출이 함께 개선된다.
2. 문서마다 정규화 스크립트를 실행한다. 수동 보정이 반복되고 재파싱 때 재발한다.
3. 검색 리랭커부터 조정한다. 색인에 없는 본문은 검색 순위 조정으로 복구할 수 없다.

## 권장 설계

- 루트부터 text block의 kids를 원래 읽기 순서대로 순회한다.
- table과 list는 하나의 블록으로 유지하고 내부 셀이나 항목을 전역 본문으로 펼치지 않는다.
- 자식 블록에 page number가 없으면 가장 가까운 상위 text block의 페이지를 사용한다.
  자식의 명시적 페이지가 우선하며 원본 JSON 트리는 수정하지 않는다.
- kids 없이 content만 있는 text block은 문단으로 취급한다. content와 kids가 동시에
  있는 구조는 실제 데이터에서 확인되지 않았으므로, 명시적인 오류로 알리고 임의로
  중복 텍스트를 합성하지 않는다. 실제 지원 요구가 확인되면 별도 규칙을 정한다.
- 일반 문단·제목·표·목록의 기존 평면 입력 동작은 회귀 테스트로 보존한다.
- 빈 컨테이너와 dict가 아닌 자식은 본문으로 생성하지 않는다.

## 검증과 완료 기준

1. 중첩 제목·문단이 사라지는 실패 테스트를 먼저 작성한다.
2. 두 단계 이상 중첩, 형제 블록 순서, 페이지 상속과 자식 우선순위,
   표·목록 원자성, 원본 불변성, 직접 content 처리를 검증한다.
3. 청커에서 중첩 본문의 고유 문구와 제목 경로가 생성되는지 검증한다.
4. 메타데이터 추출이 중첩된 연도·제목을 볼 수 있는지 검증한다.
5. 원본 백업을 복사하거나 읽기 전용으로 열어 수동 보정 구조와 비교한다.
   운영 Qdrant에 재색인하거나 임베딩을 생성하지 않는다.
6. `uv run pytest -q` 전체 통과와 변경 diff 검토 후 작은 단위로 커밋한다.
